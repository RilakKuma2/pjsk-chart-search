# Playback visual sources

- Native `live/note/custom01` and `custom02`: playback is fixed to `custom02` in `public/playback/skin2`; body sprites are 354 × 186, PPU 108, horizontal sliced borders 100 px. The trace body (`notes_4/5/6`) and center marker are separate renderers.
- `LiveUtility.CalcSpriteRendererSize`: body width `1.217778 × (laneCount − 1) + 2.06`, height `1.722222`. See `playbackNoteSource.json` and `playbackGeometry.js`.
- `FlickNoteView.Move` (ISIL address `0x061889A4`): `ScrollCount = 2`, translation `2 × frac(chartTime × 2)`, alpha `1 − clamp(translation − 1, 0, 1)`. Arrow PPU 108, pivot `(0.5, 0)`; diagonal movement root has a 30° rotation. Movement uses chart time, so pause, seeking, repeat and playback rate remain synchronized.
- `NoteLineView.Setup` / `NotesViewManager`: `longNoteLine.png` and `traceLine_eff.png`; The line atlas has four distinct color/state bands. Sample a single row per rail, not a vertical gradient repeated for every segment. The native UV boundary offsets `.125` / `.875` exclude transparent outer padding from the lane span. Adjacent segments share GPU mesh edges to avoid repeated alpha blending and seams. User brightness multiplies texture alpha, default 100%. Mesh sampling follows native default split count 100.
- Native `effect_asset/live/tap_effect/0`: `scripts/extract-playback-effects.py` exports all 153 enabled particle systems in the selected tap/flick/trace/connection/lane prefabs. No filter discards moving particles or systems named `Particle`. Disabled renderers and inactive ancestors are excluded. Original atlases, per-particle sheet cells and animated flick frames are retained.
- `TapEffectView.TapAura` / `TapLane`: native ISIL loops from `laneStart` through `laneEnd`, spawning at `CalcLaneTransformX(lane)`. `TapGen` spawns once at the note center **without changing scale**. `FlickSlash` alone explicitly sets root scale `(laneEnd - laneStart + 1, 1, 1)` and Z rotation ±15°. The earlier web-only continuous-width formula has been removed. Layer overlap is composited using the native shader outputs rather than separately cropped Canvas rectangles.
- Particle TRS respects `ParticleSystemScalingMode`: `Hierarchy` uses cumulative scale, `Local` uses only the particle system's own transform scale, `Shape` scales emission positions only. Previously the exporter incorrectly multiplied ancestor scales for all three modes, enlarging several critical burst layers.
- `playbackParticles.js`: native burst count/repeat interval/probability/max-particle capacity, random min/max lifetime/size/rotation/color, sphere/hemisphere/cone/box/circle emission, burst-spread arc, velocity/force/gravity, size/color-over-life, texture sheet animation and stretched billboards. PhysicsManager in the current APK has gravity `(0, -9.8100004196167, 0)`. Random seeds are stable for seeking/replay; they do not reproduce Unity's RNG sequence. Four patterns per system are prepared once and reused.
- `playbackParticleRenderer.js`: GPU particle quads, perspective-correct UV interpolation and near-plane clipping. Fragment output is `rgb = texture.rgb × tint.rgb × texture.a × tint.a`, `alpha = Custom1X > .5 ? 0 : texture.a × tint.a`, with `ONE / ONE_MINUS_SRC_ALPHA`, matching `Sekai/Note/Particles/Additive+AlphaBlend`. No baked 17-step RGB approximation remains. Renderer order is preserved across layer groups.

C# / ISIL reference: local `sekai-statics_local/apk_decompiled`, and `RilakKuma2/180mmd` branch `codex/generic-pmx-vmd-library`, commit `9a7f0ea857ea9468457ef0b3def4af246a3b7ef4` (remote head checked during this audit). Methods: `TapEffectView.TapAura`, `TapGen`, `TapLane`, `FlickSlash`; `LiveFrontView.SetupTapEffect`. Unity enum definitions: https://github.com/Unity-Technologies/UnityCsReference/blob/master/Modules/ParticleSystem/Managed/ParticleSystemEnums.cs.

## Verification limits

This is a data-driven web renderer, not Unity's native particle engine. Unity's proprietary damping integration was not recovered: the web simulator uses native limiter/dampen values at a fixed 60 Hz step. Random distribution/sequence and stretched-billboard construction have not been compared frame-for-frame with the app. Camera framing and jacket placement now come from the APK prefabs. Safe-area anchor config overrides, live HUD score/life simulation, and exact Unity billboard size limiting are not implemented; the requested hidden AUTO/header elements remain hidden. On devices without WebGL, the Canvas fallback does not reproduce per-particle RGB tint or perspective-correct interpolation. Do not label these parts pixel-identical or fully verified.

`node --test tests/playback-effects.test.js` checks source layer coverage, native capacity/burst repeat, shape bounds, random/animated atlas cells, stepped curves, trajectory finiteness and time integration. Native OpenGL compiled and linked the particle shaders after translating GLSL ES to GLSL 1.20; this is not a browser or in-game visual comparison. No browser was used during this audit.

- Current APK `live/view/frontuiview`: EffectCamera position `(0,5.320000171661377,-5.860000133514404)`, rotation quaternion `(0.23429381847381592,0,0,0.9721658229827881)`, field of view 50°. FrontCamera orthographic size 5. Particle projection now uses that full camera and FOV with `SekaiCameraAspect` correction; it no longer anchors or scales particles to the note-space judgment line.
- Interior connection markers use cubic rail interpolation for fractional lanes, matching the `ConnectionNoteView` use of `LaneStartF` / `LaneEndF`. Ambiguous crossing paths retain their original marker position.

## Native layout and input/judgment audit

- `scripts/extract-playback-layout.py` reads the APK prefabs `7ccedf6780c404baab54a7e063e2e693` (Background2DView) and `426ec9b178b054fe38fd5d6e5cecce0a` (FrontUIView), including split serialized files, external sprite references, pivots, PPU, TRS, sorting and mask cutoff. Output is `playbackLayout.json` and the original sprites under `public/playback/layout`.
- CameraSizeUpdater's serialized values are **1920 × 1080, PPU 108, Both**. Front world units are therefore `min(width/(1920/108),height/10)`, replacing the previous screenshot-fit 19.2 × 14.4 world area. Perspective cameras widen vertical FOV below 16:9 (`SekaiCameraAspect.CalculateVerticalFov`).
- Background2DView has six jacket renderers, not four. Its camera is perspective, vertical FOV 42°, position `(0,0,-10)`. Preserve each 3D transform, reflected jacket, color, SpriteMask alpha cutoff and frame sprite. Main jacket center is `(0,1.39,0)` with scale `(0.455,0.437,1)` and X rotation. The native `music/jacket/jacket_s_074` texture was inspected: **740 × 740**; SetupJacket uses Sprite.Create's default 100 PPU. Web cover resolution does not change physical jacket size.
- Native `live/2dmode/background/default` was inspected: **2048 × 2048, PPU 87.77143096923828**. Frame/base/floor sprites use their own exported PPU/pivots. They are not recreated with CSS rounded rectangles. The web renderer caches the composition at the current screen resolution, rebuilding only after image loading or resize.
- `LaneRoot` position is `(0,-0.8000000119,0)`. Original `lane_base`, `lane_line` and `judgeLine` sprites replace handmade line/trapezoid drawing. JudgeLane local Y is `-2.1199998856` (world Y `-2.9199998975`). Native pause sprite `btn_stop` is **96 × 96 at PPU 108**; right-top offset comes from the prefab anchor. Device-specific ClientConfig safe-area adjustments are not guessed.
- **Touch is distinct from judgment:** `TapEffectView.Unpicked → PlayUnpickedEffect → tapLaneEffectList / FX_LANE_TAP`. Successful notes use `Excute → TapLane + TapAura + TapGen` (plus FlickSlash for flicks), with separate Connection/Friction paths. The preview exports no `fx_lane_tap` and does not manufacture touch events during automatic playback.
- The successful-note aura/lane implementations genuinely iterate inclusive lanes; the central burst is emitted once. These overlapping layers visually form a wider effect. `LiveUtility.CalcLaneTransformX` is `0.84 × lane − 4.62`, **not** the notes' 1.19 pitch. The previous preview used note spacing and a judgment anchor for both, making the aura size/spacing wrong. It also shrank the 70-unit-long illumination texture with an invented world-size cap; that cap has been removed. Preserve the source max-size metadata, but do not claim to reproduce Unity's native screen-space particle limiter.
- `playbackProjection.js` is shared by GPU and Canvas effect projection. `playback-layout.test.js` checks 16:9/4:3/ultrawide scaling, native effect hit positions, overlapping aura widths, exclusion of the unpicked effect, all six mask homographies and exported asset dimensions. Canvas fallback retains the layout but approximates tilted quads with two affine triangles and lacks native RGB tint / binary stencil edges.
- An offline Pillow projection of the extracted background was inspected without opening a browser. This checks source layout composition, **not** browser rendering or frame-for-frame comparison with gameplay.

## Simplified effects

`OptionLiveSetting.Setup` / save maps the note-effect toggle to `LiveSettingData.NoteEffect` 0 or 1. `LiveConfig.SetNoteEffectName` selects `effect_asset/live/tap_effect/{index}`. Both native bundles were read; preset 1 retains the same selected 153 particle renderers, but changes their initial color/alpha (many to one quarter), some emission bursts and trace speed/gradient values. It is not equivalent to disabling the central bursts or applying one global alpha multiplier.

`playbackEffectsSimple.json` contains property differences extracted from bundle 1 against bundle 0, matched by prefab hierarchy path. Reproduce with `python3 scripts/extract-playback-effects.py /path/to/tap_effect/1 playbackEffectsSimple.json playbackEffects.json`. Playback starts with simplification enabled; the separate effect visibility toggle still disables all effects. Both templates are prepared once, so switching presets preserves playback time and does not reload the chart. The exit control uses a white circular back arrow, matching the pause control's dimensions, vertical position and opposite edge offset; it retains a localized accessible name.

## Cover and mirror audit

`LiveUtility.CalcNoteShowRatePosition` (ISIL `0x04C03244`) interpolates from `spawn + (judgment - spawn) × 0.072650254`, then toward judgment by the covered fraction. `NoteShowRateView.Setup` interpolates its serialized line sizes (1.1 × .03 to 14.12 × .06), places the line just above the cutoff, and uses the native `HideArea` / `Line` sprites with alpha .6. The slide shader discards fragments whose screen Y exceeds `_NoteShowRate`. Playback now clips hidden notes/ribbons at that boundary and draws the exported mask and line instead of a handmade opaque triangle. Cover zero disables the mask. Connection/trace judgment effects now receive the mirror flag, just like normal hits and flicks.

## Sustained holds

`LivePrefabDefine.FX_LONG_HOLD_AURA` is **fx_note_hold_aura**; the critical counterpart is **fx_note_critical_long_hold_gen_aura** (not a name guessed from the normal tap suffix). Gen prefabs are `fx_note_long_hold_gen` / `fx_note_critical_long_hold_gen`. Both native presets now export these additional 30 renderers, bringing the selected total to 183. `LongTapEffectView.Excute` sets both roots to the continuous note center and scales **Aura only** to `LaneEndF + 1 - LaneStartF` (ARM64 `0x06192FA8..0x06192FC0`); Gen retains its scale. The web renderer applies the aura width while respecting hierarchy/local particle scaling.

Exported emission rates, loop flags and simulation spaces drive the sustained effects. The presets use constant rates of 2–30 particles/s, plus bursts. `moveWithTransform` 0 is local space (follows the hold); 1 is world space (retains its birth position). Initial nonlooping flashes run only once. Connected cubic rail sections share one clock, and guide paths do not emit hold effects. Position is solved at the current chart time or particle birth time as appropriate. On note end, `ParticleSystemController.Stop` calls `StopEmittingAndClear`; no hold particles persist after that boundary.

Prepared particle trajectories are reused over bounded live cycles; no whole-song particle simulation or growing per-hold cache is needed. Pause, rate, seek and repeat all sample chart time. Tests cover native limits across cycle boundaries for both presets, connected/crossing paths, and an actual renderer invocation with a recording Canvas in Node (no browser). Unity RNG/integration and device-specific visual limits noted above remain verification limitations, not claims of exact native equivalence.
